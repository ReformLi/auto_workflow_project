### 1. 项目概述

本项目是一个基于 PyQt5 和 NodeGraphQt 构建的 Windows 窗口自动化工作流可视化编辑器。用户通过拖拽节点、连线编排自动化流程，并实际执行鼠标、键盘、窗口、图像识别、OCR 等操作。系统支持多工作流并行执行、后台操作优先、执行状态可视化、工作流验证与调试等特性，旨在为非专业开发者提供直观、高效且不干扰用户的自动化工具。

### 2. 设计目标

- **易用性**：降低自动化流程搭建门槛，通过可视化节点和直观的配置交互提升效率。
- **可靠性**：提供工作流验证、执行状态反馈、结果徽章、后台降级机制，确保执行可预测、可调试。
- **灵活性**：支持复杂流程控制（条件、循环、并行）和多种自动化操作，满足多样化场景。
- **非侵入性**：优先后台执行，减少对用户当前操作的干扰；仅必要时转前台。
- **可维护性**：节点职责单一，模块化设计，支持多工作流实例和独立资源管理。
- **性能**：优化 UI 渲染与图像匹配效率，控制内存占用。

#### 3.2 流程控制节点

##### 3.2.1 开始节点

- **描述**：工作流唯一入口（保留）。
- **端口**：仅输出端口 `out`。
- **属性**：无。
- **行为**：工作流执行从该节点开始。

##### 3.2.2 结束节点

- **描述**：工作流唯一出口（可选，但建议保留）。
- **端口**：仅输入端口 `in`。
- **属性**：无。
- **行为**：当任意结束节点被触发时，工作流停止（若存在多个结束节点，任一触发即停止）。

> 注：若用户未添加结束节点，执行器将把没有输出连接的节点视为分支自然结束，但验证时给出提示。

##### 3.2.3 条件判断节点

- **输入端口**：
  - `input`（通用，可选，可接收任意类型）：待判断的数据，表达式内以变量 `input` 引用；未连接时可忽略（只读全局 `context` 或常量）。
- **输出端口**：
  - `true`：条件成立时触发。
  - `false`：条件不成立时触发。
- **属性**：
  - **条件表达式**（多行文本）：安全表达式求值（`safe_eval`，不支持任意代码执行）。支持：
    - 变量 `input`：输入端口值；
    - 变量 `context`：上游全部输出数据，如 `context["窗口对象"]`；
    - 运算符与白名单方法/函数：`> < == and or not`、`startswith/endswith/get/...`、`len/str/int/...`。
  - 示例：`input > 5 and input < 10`、`input.startswith("错误")`、`context["window_exists"] == True`。
  - **比较模板按钮**：属性面板提供 大于 / 小于 / 等于 / 包含 四个快速模板，点击自动填充表达式。
- **界面**：属性页（双击节点 / 右键→属性）编辑完整表达式；节点体上仅显示截断的表达式摘要（压缩空白后取前 18 字符）。

##### 3.2.4 循环判断节点

- **输入端口**：
  - `in`：进入判断（通常接开始节点）。
- **输出端口**：
  - `true`：继续循环（连接「循环入口」的 `enter`）。
  - `false`：退出循环（连接循环体之后的节点）。
- **属性**：
  - **循环模式**（下拉，默认「计数器模式」）：
    - **计数器模式**：按循环次数。**循环次数** 默认 `3`。运行时不在意节点数值，剩余次数存节点内部运行时状态，执行前由 `reset()` 清零，可重复执行。
    - **条件值模式**：按**条件表达式**求值（全局 `input` 变量、`context["键"]` 及白名单方法/函数，同条件判断节点），求值为真继续循环、为假退出。含 大于/小于/等于/包含 比较模板按钮。
- **界面**：属性页（双击 / 右键→属性）编辑；按「循环模式」联动显隐「循环次数/条件表达式」；节点体下方显示摘要（计数器显示"循环 N 次"，条件值显示截断表达式）。

##### 3.2.5 循环入口节点（过渡节点）

- **作用**：循环体入口/回路的过渡节点；首次进入开启循环体，循环体末尾回流时重新触发循环判断，形成回路。
- **输入端口**：
  - `enter`：首次进入（连接循环判断的 `true` 输出）。
  - `next`：循环体末尾回流（连接循环体最后一个节点的输出）。
- **输出端口**：
  - `body`：进入循环体，连接循环体第一个节点。
- **连接规则**：
  - `enter` 只能连接判断型节点的 `true` 输出；`next` 接循环体末尾；`body` 接循环体首节点；判断节点的 `false` 接循环体之后的节点。
  - 验证时会对上述连接给出 ⚠ 警告（不阻断）。
- **界面**：带循环图标、节点体标示"循环入口"；无属性（双击 / 右键不弹出属性页）。

典型连接（形成回路）：
```
开始 → 循环判断.in
循环判断.true → 循环入口.enter
循环入口.body → [循环体首个节点] … 循环体末尾节点 → 循环入口.next
循环判断.false → 循环体之后的节点
执行：判断 true → 进入循环体 → 循环入口.next 触发 → 重新判断 → … → false 退出。
```

##### 3.2.6 等待节点

- **输入端口**：`in`
- **输出端口**：`out`
- **属性**：等待时长（秒，支持小数）。
- **行为**：延时指定时间后继续。

##### 3.2.7 重试执行节点 ✅ 已实现（本次新增）

把"失败后重试"高频模式内建为单节点，替代手工 循环判断+循环入口 回路。

- **输入端口**：
  - `in`：首次进入。
  - `retry`（可多连）：失败回流——连接尝试链中节点的 `fail` 出口。
- **输出端口**：
  - `body`：执行体入口，连接第一次尝试的首个节点。
  - `用尽`：重试次数用尽后的补救出口（可不连接，此时结束流程）。
- **属性**：重试次数（默认 3，指失败后额外重试次数）、重试间隔（秒）。
- **典型连接**：
```
重试执行.body → 操作A → 操作B
操作A.fail / 操作B.fail → 重试执行.retry
重试执行.用尽 → 补救流程
```

##### 3.2.8 等待图片 / 等待窗口节点 ✅ 已实现（本次新增）

轮询直到目标出现或超时，替代"固定等待 + 碰运气"。

- **等待图片**：继承查找图片节点的全部配置（复用 ImageNodeEditor 编辑器），按阈值反复匹配。
  输出：`出现` / `超时`（流程出口），命中后照常输出 `坐标` / `中心坐标` / `匹配度`。
- **等待窗口**：按标题/类名/进程名反复查找（支持捕获按钮）。
  输出：`出现` / `超时`，出现后输出 `窗口对象` / `窗口句柄`（可直接供激活窗口/鼠标点击）。
- **公共属性**：超时（秒，默认 10）、轮询间隔（秒，默认 0.5）。
- **行为**：出现 → 走「出现」出口；超时 → 走「超时」出口（可接补救流程）。执行期间响应终止/暂停。

##### 3.2.9 子工作流节点 ✅ 已实现（本次新增）

把另一个 `.awflow` / `.json` 工作流文件作为一个节点嵌入执行，实现流程复用。

- **端口**：`in` → `out`，另有 `fail` 出口（子流程内部失败且未接 fail 分支时流转）。
- **属性**：子工作流路径（属性页提供 浏览… 按钮与文件有效性检查）。
- **行为**：执行时加载文件，从其「开始」节点同步执行到结束（独立运行、支持内部条件/循环/重试）。
  嵌套最多 8 层（防自调用死循环）；执行期间响应终止/暂停。
- **实现**：`nodes/subflow_node.py` + `nodes/_control_common.py`（无头图同步执行器）+ `ui/node_subflow_widget.py`（编辑器）。

#### 3.3 窗口操作节点

所有窗口操作节点均支持**执行模式**（自动/后台/前台）。节点属性统一收纳在**属性页**（节点图上只显示节点本身）：**双击节点**或**右键节点→属性**唤起；修改自动写回节点。

##### 3.3.1 查找窗口节点

- **输入端口**：无。
- **输出端口**：
  - `window`：窗口对象。
  - `handle`：窗口句柄（HWND，整数）。
- **属性**：
  - **窗口标题**：支持完全匹配、包含、正则表达式。
  - **窗口类名**（可选）。
  - **进程名**（可选）。
  - **“捕获”按钮**：通过点击屏幕自动获取标题/类名（见 3.3.4）。
- **行为**：查找匹配窗口，若找到输出窗口对象和句柄，未找到则输出空并标记失败。

##### 3.3.2 激活窗口节点

- **输入端口**：
  - `window`（可选）：窗口对象，若连接则直接激活。
- **输出端口**：无。
- **属性**：
  - **窗口标题**：仅在未连接输入时使用，匹配方式固定为“包含”。
  - **捕获按钮**（同查找窗口）。
  - **执行模式**。
- **行为**：激活目标窗口（前台激活，或者后台仅获取焦点）。

##### 3.3.3 点击捕获辅助工具

- **适用范围**：查找窗口、激活窗口、查找图片（模板截图）等。
- **交互流程**：
  1. 属性面板中点击“捕获”按钮。
  2. 主窗口自动隐藏/最小化，鼠标变为十字准星。
  3. 用户点击目标窗口或区域。
  4. 程序获取窗口标题、类名、进程名（或截图区域）自动填入。
  5. 界面恢复。
- **技术**：全局鼠标钩子、`WindowFromPoint`、`uiautomation`/`win32gui`。

#### 3.4 输入模拟节点

所有输入节点均支持执行模式（自动/后台/前台）及前后等待。

##### 3.4.1 鼠标点击节点

- **输入端口**：
  - `coords`（可选）：坐标数据，格式 `(x, y)` 或 `{"x":..., "y":...}`。
  - `window`（可选）：窗口句柄，用于相对坐标或后台目标。
- **输出端口**：无。
- **属性**：
  - **鼠标按钮**：左键/中键/右键。
  - **点击类型**：单击/双击。
  - **坐标模式**：手动输入（X/Y输入框）/ 屏幕捕获（捕获按钮）/ 使用输入端口。
  - **坐标类型**：绝对屏幕坐标 / 相对窗口客户区坐标（需要窗口输入）。
  - **偏移量**：dx, dy（可选）。
  - **执行模式**。
  - **双击间隔**（毫秒，双击时有效）。
  - **移动选项**：
    - 点击前移动鼠标（仅前台有效）。
    - 点击后恢复鼠标位置（仅前台有效）。
- **行为**：按照配置执行鼠标点击。若连接 `coords` 输入，则优先使用该坐标。

##### 3.4.2 键盘快捷键节点

- **输入端口**：
  - `window`（可选）：目标窗口句柄（后台模式）。
- **输出端口**：无。
- **属性**：
  - **快捷键**：组合键输入框，支持捕获按键（如 Ctrl+Shift+A）或从下拉列表选择常用键（Enter、Tab、F1-F12等）。
  - **发送次数**（默认1）。
  - **按键间隔**（毫秒，多次发送时）。
  - **执行模式**。
- **行为**：模拟组合键输入。后台模式使用 `PostMessage`，前台模式使用 `SendInput`。

##### 3.4.3 文本输入节点

- **输入端口**：
  - `text`（可选）：要输入的字符串，若连接则使用输入值。
  - `window`（可选）：目标窗口句柄。
- **输出端口**：无（或可选原样输出文本）。
- **属性**：
  - **文本内容**：多行文本编辑框。
  - **输入方式**（自动/后台/前台）：后台优先使用剪贴板粘贴或 `WM_SETTEXT`，前台使用逐键模拟。
  - **清空剪贴板**：粘贴前清空剪贴板并恢复（后台）。
  - **发送间隔**（逐键输入延迟，毫秒）。
  - **执行模式**。
- **行为**：输入文本字符串，支持 Unicode。

#### 3.5 图像与 OCR 节点

##### 3.5.1 查找图片节点

- **输入端口**：
  - `窗口对象`（可选）：限定搜索窗口区域；未连接时全屏搜索。
- **输出端口**：
  - `坐标`：匹配区域的左上角坐标 `(x, y)`（颜色定位时为基准点坐标）。
  - `中心坐标`：匹配区域中心坐标（含偏移量）。
  - `匹配度`：匹配置信度（0~1，模板匹配为算法值，颜色定位为颜色吻合度）。
- **模式**（下拉）：`模板匹配` / `颜色定位`。
  - **模板匹配**：基于 OpenCV 模板匹配（TM_CCOEFF_NORMED），屏幕与模板一致预处理后检索。
  - **颜色定位**：多点颜色组合定位，对缩放/光照有一定鲁棒性。
- **模板图片区**（模板匹配模式）：
  - **粘贴**（Ctrl+V）：从剪贴板读取图片。
  - **拖拽**：从文件管理器拖入图片文件。
  - **浏览…**：文件选择对话框（png/jpg/jpeg/bmp）。
  - **截屏…**：十字准星框选屏幕区域直接生成模板。
  - **清除**：清空当前模板；缩略图预览（128×128）。
- **颜色定位区**（颜色定位模式）：
  - **开始采集**：主窗口最小化，十字准星左键逐点采集屏幕颜色，右键或 Esc 结束；≥1 个点（建议 3 个以上增强鲁棒性），以第 1 个点为基准计算相对坐标。
  - 采集点以彩色圆点 + 相对坐标展示，支持「清除要点」。
  - **容差**：逐通道颜色偏差允许范围（0~255，默认 40）。
- **参数**：
  - **阈值**（0~1，默认 0.8）：最低匹配置信度，低于则视为未找到。
  - **偏移 X / Y**：在识别坐标基础上叠加偏移（点击/中心坐标均生效）。
  - **预处理**（`无` / `灰度` / `二值化`）：灰度、二值化可增强特定场景匹配效果。
  - **命中后自动点击**：识别成功后自动在偏移后的中心坐标处执行鼠标点击。
- **测试识别**：按钮在属性面板中触发，后台线程在当前屏幕执行一次匹配，返回匹配度、坐标及命中区域缩略图，不干扰工作流执行状态。
- **序列化**：
  - `template_path`：图片来自文件时的路径；
  - `template_data`：粘贴/截屏图片转 Base64（PNG，内嵌）；
  - 加载时内嵌数据优先，缺失时回退读取文件路径；颜色定位仅存储点列表（JSON 体积小）。
- **实现**：`automation/image_finder.py`（匹配/颜色定位核心）、`nodes/image_nodes.py`（节点执行）、`ui/node_image_widget.py`（属性编辑器，含截屏采集器与后台测试线程）。

##### 3.5.2 OCR 识别节点 ✅ 已实现

- **实现文件**：`automation/ocr.py`（引擎）、`nodes/ocr_nodes.py`（节点）、`ui/node_ocr_widget.py`（自定义属性编辑器）。
- **引擎**：直接以子进程调用系统已安装的 Tesseract（`tesseract.exe`，零新增 Python 依赖），TSV 结构化输出。
- **输入端口**：
  - `窗口对象`（可选）：限定识别窗口。
- **输出端口**：
  - `text`：完整文本。
  - `results`：结构化结果列表（文本块内容、坐标、置信度）。
- **属性**（由 OcrNodeEditor 渲染）：
  - **识别语言**：简体中文 / 英文 / 简体中文+英文（chi_sim / eng）。
  - **识别区域**：全屏 / 窗口全部 / 窗口内框选（相对窗口偏移）/ 屏幕框选。
  - **预处理**：无 / 灰度 / 二值化。
  - **最低置信度**（min_conf）。
  - **分段模式（PSM）**：自动 / 单行文本 / 单字 / 稀疏。

##### 3.7.5 fail 失败分支端口 ✅ 已实现（本次新增）

  均有红色 `fail` 输出端口。

### 4. 非功能需求

#### 4.1 性能要求

- UI 操作响应时间 < 100ms（节点拖拽、缩放）。
- 图像匹配（全屏）耗时 < 500ms（典型模板尺寸）。
- 后台操作应尽量快速，避免阻塞主线程。
- 多工作流并行时，内存占用增加可控（每个工作流实例 < 50MB）。

#### 4.2 稳定性

- 后台操作失败不得导致崩溃，应记录日志并可能降级。
- 全局钩子（点击捕获）需妥善释放，防止系统卡死。
- 多执行实例隔离状态，避免相互干扰。

#### 4.3 兼容性

- Windows 10/11 64 位，Python 3.11+。
- 屏幕 DPI 缩放适配（至少支持 100%、125%、150%）。

#### 4.4 可维护性

- 节点基类封装通用逻辑（等待、结果徽章、执行模式）。
- 自动化操作模块与 UI 解耦，便于测试。

#### 4.5 用户界面

- 深色专业工具风，颜色仅用于节点分类和执行状态。
- 节点图标使用 qtawesome 矢量图标。

### 6. 风险与应对

- **后台操作兼容性**：部分应用不响应后台消息 → 提供自动降级和用户提示。
- **全局钩子异常**：点击捕获可能卡死 → 使用超时和异常恢复机制。
- **多实例资源竞争**：剪贴板、全局快捷键等共享资源 → 执行实例间加锁或提示。
- **循环结构误用**：无限循环 → 运行时最大循环次数保护和超时。
- **颜色定位 DPI 问题**：不同缩放比例导致坐标偏移 → 统一使用物理像素或提供 DPI 感知设置。
- **OCR 依赖**：外部库安装问题 → 提供安装检查或使用 Windows 内置 OCR。
