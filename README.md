## 自动工作流设计器 — 完整需求规格说明书（V3.0 综合版）

### 1. 项目概述

本项目是一个基于 PyQt5 和 NodeGraphQt 构建的 Windows 窗口自动化工作流可视化编辑器。用户通过拖拽节点、连线编排自动化流程，并实际执行鼠标、键盘、窗口、图像识别、OCR 等操作。系统支持多工作流并行执行、后台操作优先、执行状态可视化、工作流验证与调试等特性，旨在为非专业开发者提供直观、高效且不干扰用户的自动化工具。

### 2. 设计目标

- **易用性**：降低自动化流程搭建门槛，通过可视化节点和直观的配置交互提升效率。
- **可靠性**：提供工作流验证、执行状态反馈、结果徽章、后台降级机制，确保执行可预测、可调试。
- **灵活性**：支持复杂流程控制（条件、循环、并行）和多种自动化操作，满足多样化场景。
- **非侵入性**：优先后台执行，减少对用户当前操作的干扰；仅必要时转前台。
- **可维护性**：节点职责单一，模块化设计，支持多工作流实例和独立资源管理。
- **性能**：优化 UI 渲染与图像匹配效率，控制内存占用。

### 3. 功能需求

#### 3.1 节点体系总览

节点按功能分组，定义如下分类及颜色标识（颜色仅用于语义区分，不影响功能）：

| 分组    | 分类    | 颜色        | 包含节点                          |

| 流程    | 开始    | `#3fb950` | 开始                            |
| 流程    | 结束    | `#f85149` | 结束                            |
| 控制流   | 条件判断  | `#d29922` | 条件判断、循环判断                     |
| 控制流   | 循环    | `#a371f7` | 循环承接、固定次数循环（可选）               |
| 控制流   | 等待    | `#8b949e` | 等待                            |

| 自动化操作 | 图像识别  | `#db61a2` | 查找图片（含颜色定位）、OCR 识别            |
| 自动化操作 | 系统操作  | `#f0883e` | 启动程序、结束进程、执行命令行、系统操作          |

| 调试    | 辅助    | `#6e7681` | 日志输出、消息弹窗、注释节点                |

**节点通用特性**：

- 所有节点均继承自 `BaseNode`，支持以下通用属性：
  - **前置等待**（秒，默认 0）
  - **后置等待**（秒，默认 0）
  - **执行模式**（自动/后台/前台，仅对涉及系统输入的节点有效）
  - **结果徽章**（显示上次业务执行结果）
- 节点均支持双击非端口区域打开“快速设置”对话框，编辑常用参数和前后等待。

#### 3.2 流程控制节点

##### 3.2.1 开始节点

- **描述**：工作流唯一入口（保留）。
- **端口**：仅输出端口 `out`。
- **属性**：无。
- **行为**：工作流执行从该节点开始。

##### 3.2.2 结束节点

- **描述**：工作流唯一出口（可选，但建议保留）。
- **端口**：仅输入端口 `in`。
- **属性**：无。
- **行为**：当任意结束节点被触发时，工作流停止（若存在多个结束节点，任一触发即停止）。

> 注：若用户未添加结束节点，执行器将把没有输出连接的节点视为分支自然结束，但验证时给出提示。

##### 3.2.3 条件判断节点

- **输入端口**：
  - `input`（通用，可选）：待判断的数据；未连接时使用全局上下文中的 `input` 变量或表达式内置变量。
- **输出端口**：
  - `true`：条件成立时触发。
  - `false`：条件不成立时触发。
- **属性**：
  - **条件表达式**（字符串）：使用安全表达式求值，支持变量 `input` 及全局上下文中其他键值。示例：`input > 5 and input < 10`。
  - 提供常用比较模板按钮（大于、小于、等于、包含等）辅助输入。
- **界面**：节点上显示表达式摘要。

##### 3.2.4 循环判断节点

- **输入端口**：
  - `input`（通用，可选）：循环条件值或循环变量；未连接时可使用内部计数器。
- **输出端口**：
  - `cycle`：条件为真，继续循环。
  - `end`：条件为假，退出循环。
- **属性**：
  - **条件表达式**（字符串）：同条件判断节点，支持 `input` 和上下文变量。
  - **循环模式**（可选）：`表达式模式` / `计数器模式`（设置初始次数，每次循环递减）。
- **行为**：当 `cycle` 被触发，执行循环体；循环体执行完毕通过循环承接节点回流，再次触发本节点判断。

##### 3.2.5 循环承接节点（过渡节点）

- **输入端口**：
  - `enter`：首次进入循环体（连接循环判断节点的 `cycle`）。
  - `next`：循环体结束后回流（连接循环体最后一个节点的输出）。
- **输出端口**：
  - `body`：连接循环体第一个节点。
- **行为**：
  - 当 `enter` 触发时，激活 `body` 输出，开始循环体。
  - 当 `next` 触发时，再次触发循环判断节点（通过内部连接或要求显式连接），形成回路。
- **界面**：特殊外观（圆形或循环图标），自动高亮循环回路，提供连接校验。

##### 3.2.6 固定次数循环节点（可选）

- **输入端口**：无。
- **输出端口**：
  - `cycle`：每次循环触发。
  - `done`：循环结束后触发。
- **属性**：循环次数（整数）。
- **行为**：内部管理计数器，循环体末尾节点需连接回本节点（通过输入端口或自动回流）。

##### 3.2.7 等待节点

- **输入端口**：`in`
- **输出端口**：`out`
- **属性**：等待时长（秒，支持小数）。
- **行为**：延时指定时间后继续。

#### 3.3 窗口操作节点

所有窗口操作节点均支持**执行模式**（自动/后台/前台）。

##### 3.3.1 查找窗口节点

- **输入端口**：无。
- **输出端口**：
  - `window`：窗口对象。
  - `handle`：窗口句柄（HWND，整数）。
- **属性**：
  - **窗口标题**：支持完全匹配、包含、正则表达式。
  - **窗口类名**（可选）。
  - **进程名**（可选）。
  - **“捕获”按钮**：通过点击屏幕自动获取标题/类名（见 3.3.4）。
- **行为**：查找匹配窗口，若找到输出窗口对象和句柄，未找到则输出空并标记失败。

##### 3.3.2 激活窗口节点

- **输入端口**：
  - `window`（可选）：窗口对象，若连接则直接激活。
- **输出端口**：无。
- **属性**：
  - **窗口标题**：仅在未连接输入时使用。
  - **窗口类名**、**进程名**（可选）。
  - **捕获按钮**（同查找窗口）。
  - **执行模式**。
- **行为**：激活目标窗口（前台激活，或者后台仅获取焦点）。

##### 3.3.3 查找并激活窗口节点（复合节点）

- **输入端口**：无。
- **输出端口**：
  - `window`：窗口对象。
  - `handle`：窗口句柄。
- **属性**：同“查找窗口”节点（标题、类名、进程名、捕获按钮） + 执行模式。
- **行为**：查找并激活窗口，成功则输出，失败标记。

##### 3.3.4 点击捕获辅助工具

- **适用范围**：查找窗口、激活窗口、查找并激活窗口、查找图片（模板截图）等。
- **交互流程**：
  1. 属性面板中点击“捕获”按钮。
  2. 主窗口自动隐藏/最小化，鼠标变为十字准星。
  3. 用户点击目标窗口或区域。
  4. 程序获取窗口标题、类名、进程名（或截图区域）自动填入。
  5. 界面恢复。
- **技术**：全局鼠标钩子、`WindowFromPoint`、`uiautomation`/`win32gui`。

##### 3.3.5 关闭窗口节点

- **输入端口**：
  - `window`（可选）：窗口对象。
  - `handle`（可选）：窗口句柄。
- **输出端口**：无。
- **属性**：
  - **关闭方式**：正常关闭（WM_CLOSE）、强制结束进程（TerminateProcess）。
  - **窗口标题**：未连接输入时使用。
- **行为**：关闭目标窗口或进程。

##### 3.3.6 设置窗口状态节点

- **输入端口**：
  - `window` / `handle`（可选）。
- **输出端口**：无。
- **属性**：
  - **操作**：最小化、最大化、还原、置顶/取消置顶。
  - **窗口标题**（备选）。
- **行为**：对目标窗口执行状态设置。

##### 3.3.7 获取窗口信息节点（可选）

- **输入端口**：
  - `window` / `handle`（可选，未连接时使用属性中的标题查找）。
- **输出端口**：
  - `title`：窗口标题。
  - `class_name`：类名。
  - `process_name`：进程名。
  - `rect`：窗口位置和尺寸（tuple）。
- **属性**：窗口标题（备选）。
- **行为**：查询窗口信息并输出。

#### 3.4 输入模拟节点

所有输入节点均支持执行模式（自动/后台/前台）及前后等待。

##### 3.4.1 鼠标点击节点

- **输入端口**：
  - `coords`（可选）：坐标数据，格式 `(x, y)` 或 `{"x":..., "y":...}`。
  - `window`（可选）：窗口句柄，用于相对坐标或后台目标。
- **输出端口**：无。
- **属性**：
  - **鼠标按钮**：左键/中键/右键。
  - **点击类型**：单击/双击。
  - **坐标模式**：手动输入（X/Y输入框）/ 屏幕捕获（捕获按钮）/ 使用输入端口。
  - **坐标类型**：绝对屏幕坐标 / 相对窗口客户区坐标（需要窗口输入）。
  - **偏移量**：dx, dy（可选）。
  - **执行模式**。
  - **双击间隔**（毫秒，双击时有效）。
  - **移动选项**：
    - 点击前移动鼠标（仅前台有效）。
    - 点击后恢复鼠标位置（仅前台有效）。
- **行为**：按照配置执行鼠标点击。若连接 `coords` 输入，则优先使用该坐标。

##### 3.4.2 键盘快捷键节点

- **输入端口**：
  - `window`（可选）：目标窗口句柄（后台模式）。
- **输出端口**：无。
- **属性**：
  - **快捷键**：组合键输入框，支持捕获按键（如 Ctrl+Shift+A）或从下拉列表选择常用键（Enter、Tab、F1-F12等）。
  - **发送次数**（默认1）。
  - **按键间隔**（毫秒，多次发送时）。
  - **执行模式**。
- **行为**：模拟组合键输入。后台模式使用 `PostMessage`，前台模式使用 `SendInput`。

##### 3.4.3 文本输入节点

- **输入端口**：
  - `text`（可选）：要输入的字符串，若连接则使用输入值。
  - `window`（可选）：目标窗口句柄。
- **输出端口**：无（或可选原样输出文本）。
- **属性**：
  - **文本内容**：多行文本编辑框。
  - **输入方式**（自动/后台/前台）：后台优先使用剪贴板粘贴或 `WM_SETTEXT`，前台使用逐键模拟。
  - **清空剪贴板**：粘贴前清空剪贴板并恢复（后台）。
  - **发送间隔**（逐键输入延迟，毫秒）。
  - **执行模式**。
- **行为**：输入文本字符串，支持 Unicode。

#### 3.5 图像与 OCR 节点

##### 3.5.1 查找图片节点

- **输入端口**：
  - `window`（可选）：限定搜索窗口区域。
- **输出端口**：
  - `coords`：匹配坐标 `(x, y)`。
  - `confidence`：匹配度。
- **属性**：
  - **模板图片**：
    - 支持从剪贴板粘贴、拖拽文件、浏览文件选择。
    - 显示缩略图（约120x120）。
    - 支持“截取屏幕区域”作为模板（动态截图）。
  - **匹配阈值**（最低置信度，默认 0.8）。
  - **搜索区域**：全屏 / 指定窗口 / 自定义区域。
  - **图像预处理**：灰度化、二值化等（可选）。
  - **偏移量**：dx, dy（可选）。
  - **执行模式**（影响截图方式：后台使用 PrintWindow）。
  - **匹配后点击**（可选，自动执行鼠标点击）。
  - **多模板支持**（可选，依次匹配返回最佳）。
- **测试按钮**：在属性面板中执行一次识别测试，显示结果和缩略图。
- **模式**：模板匹配 / 颜色定位（多点颜色匹配）。
  - **颜色定位模式**：
    - 通过“开始采集”按钮进入屏幕取色模式，点击至少3个点，记录相对坐标和颜色值。
    - 属性面板显示颜色点列表和容差设置。
    - 匹配时扫描屏幕，检查颜色点相对位置是否匹配。
- **序列化**：图片数据保存为相对路径（资源文件夹）或 Base64（小图）。

##### 3.5.2 OCR 识别节点

- **输入端口**：
  - `window`（可选）：限定识别窗口。
  - `image`（可选）：输入图像数据（numpy 数组或文件路径）。
- **输出端口**：
  - `text`：完整文本。
  - `results`：结构化结果列表（文本块内容、坐标、置信度）。
- **属性**：
  - **识别语言**：中文、英文等（可多选）。
  - **识别区域**：全屏、窗口、自定义坐标。
  - **预处理选项**：灰度化、二值化等。
  - **最低置信度**。
  - **执行模式**（后台使用 PrintWindow 截图）。
- **实现**：可集成 `pytesseract` 或 Windows 自带 OCR API。

#### 3.6 数据与系统操作节点（新增建议）

##### 3.6.1 设置变量节点

- **输入端口**：`in`
- **输出端口**：`out`
- **属性**：变量名、变量值（支持表达式或直接输入）。
- **行为**：在全局上下文中设置变量。

##### 3.6.2 获取变量节点

- **输入端口**：无
- **输出端口**：`value`（变量值）
- **属性**：变量名。
- **行为**：从全局上下文读取变量并输出。

##### 3.6.3 日志输出节点

- **输入端口**：`in`
- **输出端口**：`out`（透传）
- **属性**：日志级别（DEBUG/INFO/WARN/ERROR）、消息内容（支持引用变量）。
- **行为**：向应用日志面板输出消息。

##### 3.6.4 启动程序节点

- **输入端口**：无
- **输出端口**：`pid`（进程ID，可选）
- **属性**：可执行文件路径、启动参数、工作目录。
- **行为**：启动外部程序。

##### 3.6.5 结束进程节点

- **输入端口**：无
- **输出端口**：无
- **属性**：进程名称或 PID。
- **行为**：结束指定进程。

##### 3.6.6 执行命令行节点

- **输入端口**：无
- **输出端口**：`output`（命令输出）
- **属性**：命令（CMD/PowerShell）、超时时间。
- **行为**：执行命令并返回输出。

##### 3.6.7 文件读写节点（可拆分为多个）

- **读取文本文件**：输入文件路径，输出文件内容。
- **写入文本文件**：输入文件路径、内容、写入模式（覆盖/追加）。
- **复制/移动/删除文件**：输入源和目标路径。

##### 3.6.8 剪贴板操作节点

- **获取剪贴板内容**：输出文本或图像。
- **设置剪贴板内容**：设置文本或图像。

##### 3.6.9 消息弹窗节点

- **输入端口**：`in`
- **输出端口**：`out` / `result`（用户选择）
- **属性**：标题、消息内容、按钮组合（确定/取消/是否）。
- **行为**：显示模态对话框，将用户选择输出。

##### 3.6.10 注释节点（仅视觉）

- **属性**：文本内容、颜色、字体大小。
- **行为**：不参与执行，仅用于画布说明。

> 以上新增节点可根据实际需求逐步实现，优先级见第 5 节。

#### 3.7 节点通用交互与视觉

##### 3.7.1 结果状态徽章

- 节点右上角显示图标，表示上次业务执行结果（成功/失败/未执行）。
- 悬停显示详细信息，点击可在属性面板展开结果详情。
- 结果数据由执行器写入节点 `result_data`。

##### 3.7.2 前后等待

- 所有节点属性面板包含“前置等待”和“后置等待”输入框（秒，可小数）。
- 双击节点弹出快速设置对话框，包含前后等待输入框和常用参数。

##### 3.7.3 执行模式

- 仅涉及系统输入的节点（鼠标、键盘、窗口激活等）提供执行模式下拉。
- 选项：自动（默认）、后台、前台。
- 后台模式失败时自动降级或提示。

##### 3.7.4 节点属性面板

- 属性面板根据节点类型动态生成控件。
- 图片类节点提供缩略图预览和测试按钮。
- 窗口类节点提供捕获按钮。
- 条件/循环节点提供表达式编辑器和模板按钮。

#### 3.8 工作流管理

##### 3.8.1 多工作流并行执行

- 主界面中央使用 `QTabWidget` 管理多个工作流画布。
- 每个标签页独立加载、编辑、执行。
- 执行管理器支持多实例，每实例独立线程、状态、日志。
- 日志统一显示，标注来源标签页标题。

##### 3.8.2 工作流文件格式

- 默认保存格式：`.awflow`（ZIP 容器）。
  - 内部包含 `workflow.json` 和 `resources/` 文件夹（存放图片等资源）。
- 兼容旧 `.json` 格式打开，保存时可选“纯 JSON + 外部资源文件夹”。
- 图片资源优先使用相对路径，缺失时使用 Base64 内嵌。

##### 3.8.3 验证与调试

- 执行前自动验证：开始/结束节点唯一性（若保留）、连线合法性、循环结构完整性。
- 支持节点级结果徽章和日志输出。
- 调试选项：高亮循环回路、显示识别匹配标记（屏幕红框）等。

##### 3.8.4 视图与快捷键

- 保留现有视图功能：网格线、缩放、面板显隐。
- 快捷键定义与现有版本一致。

### 4. 非功能需求

#### 4.1 性能要求

- UI 操作响应时间 < 100ms（节点拖拽、缩放）。
- 图像匹配（全屏）耗时 < 500ms（典型模板尺寸）。
- 后台操作应尽量快速，避免阻塞主线程。
- 多工作流并行时，内存占用增加可控（每个工作流实例 < 50MB）。

#### 4.2 稳定性

- 后台操作失败不得导致崩溃，应记录日志并可能降级。
- 全局钩子（点击捕获）需妥善释放，防止系统卡死。
- 多执行实例隔离状态，避免相互干扰。

#### 4.3 兼容性

- Windows 10/11 64 位，Python 3.11+。
- 屏幕 DPI 缩放适配（至少支持 100%、125%、150%）。

#### 4.4 可维护性

- 节点基类封装通用逻辑（等待、结果徽章、执行模式）。
- 自动化操作模块与 UI 解耦，便于测试。

#### 4.5 用户界面

- 深色专业工具风，颜色仅用于节点分类和执行状态。
- 节点图标使用 qtawesome 矢量图标。

### 6. 风险与应对

- **后台操作兼容性**：部分应用不响应后台消息 → 提供自动降级和用户提示。
- **全局钩子异常**：点击捕获可能卡死 → 使用超时和异常恢复机制。
- **多实例资源竞争**：剪贴板、全局快捷键等共享资源 → 执行实例间加锁或提示。
- **循环结构误用**：无限循环 → 运行时最大循环次数保护和超时。
- **颜色定位 DPI 问题**：不同缩放比例导致坐标偏移 → 统一使用物理像素或提供 DPI 感知设置。
- **OCR 依赖**：外部库安装问题 → 提供安装检查或使用 Windows 内置 OCR。
